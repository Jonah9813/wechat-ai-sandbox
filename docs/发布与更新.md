# 手机 App：打包、发布与自动更新

这个项目现在有两条运行方式，共用同一套前端代码：

| 场景 | 运行方式 | AI 请求 | 数据 |
| --- | --- | --- | --- |
| 电脑浏览器 | `npm run dev` / `启动微信.bat` | Vite 本地代理（`/api/chat`）；网页端用 Playwright | localStorage + `events/*.md` |
| 安卓手机 App | Capacitor + WebView | 原生 HTTP 直连 API；网页端用 App 内置 WebView | localStorage（App 私有目录，升级保留） |

App 的包名是 `com.lucky.wechatsandbox`，桌面名称是「微信沙盒」。改包名会导致新旧版本不能覆盖安装（自动更新断链），确定前不要随便改。

## 0. 最省事流程（推荐）

仓库已经建好并推送完成：

```text
https://github.com/Jonah9813/wechat-ai-sandbox
```

云端也已经用「无签名调试构建」验证过整条链路（网页打包 → Capacitor 同步 → Gradle 编译 → 产出 APK），并在 MuMu（Android 15）上实装验证：启动、收发消息、DeepSeek 网页端登录窗口都正常。

**现在只差最后一步：** 到仓库添加 4 个签名 Secret，然后打 tag 出正式版。

1. 浏览器打开 https://github.com/Jonah9813/wechat-ai-sandbox/settings/secrets/actions
2. 按 1.2 节添加 4 个 Secret；现成拷贝表在 `android/keystore/GitHub-Secrets.txt`
3. 双击 **`发布新版本.bat`**，输入 `0.1.0`
4. 等 Actions 跑完，到 Releases 下载 APK 装到手机
5. 以后改完代码：提交 → 双击「发布新版本.bat」输入更大的版本号

> 更新源是构建时注入的 `owner/repo`。如果之后改了仓库名，需要重新打 tag 构建，旧 App 仍会查旧地址。

> 不想发正式版时，可以在 Actions 页面手动点 `Run workflow`：没有 Secret 会产出调试包（可直接安装测试），有 Secret 则产出正式签名包。

## 1. 用户需要做的事（只剩配置 Secrets）

### 1.1 建一个公开的 GitHub 仓库并推送代码（已完成）

自动更新查的是 GitHub Releases 的 `latest`，所以仓库必须是 **public**（私有仓库需要 token，不建议放进 App）。

最省事：双击 `推送到GitHub.bat`，按提示粘贴仓库地址。手动命令：

```bash
cd D:\game\wechat
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

`.gitignore` 已经排除了 `node_modules`、`dist`、签名文件、参考截图、旧项目目录。

### 1.2 配置签名（只需一次，非常重要）

所有版本必须用同一个签名，否则 Android 会拒绝覆盖安装，自动更新就失效。

签名已经生成在 `android/keystore/`（**这个目录不会提交到 GitHub，也不要删**）：

- `release.keystore`：签名文件
- `release.keystore.base64`：给 GitHub Secrets 用
- `INFO.txt`：别名和密码

**当前只剩这一步没做。** 到 GitHub 仓库 → Settings → Secrets and variables → Actions → New repository secret，添加：

| Secret 名称 | 内容 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | `android/keystore/release.keystore.base64` 的完整内容（一行） |
| `ANDROID_KEYSTORE_PASSWORD` | `INFO.txt` 里的 `storePassword` |
| `ANDROID_KEY_ALIAS` | `wechatsandbox` |
| `ANDROID_KEY_PASSWORD` | 和 `storePassword` 相同 |

**请把 `android/keystore/` 另存一份到网盘/密码管理器。** 丢了就只能换新包名重新发布，老用户必须卸载重装。

### 1.3 打 tag 发布第一个版本

双击 `发布新版本.bat`，输入 `0.1.0` 即可。等价命令：

```bash
git tag v0.1.0
git push origin main --tags
```

GitHub Actions 会自动：

1. 安装 Node / JDK 21 / Android SDK
2. `npm ci` → `npm run build` → `npx cap sync android`
3. 用 Secrets 里的签名打包 release APK
4. 创建 Release，并把 `wechat-sandbox-0.1.0.apk` 挂到 Assets

在手机浏览器打开仓库的 Releases 页面，下载 APK → 允许「安装未知应用」→ 安装。

> GitHub Actions 构建记录在仓库的 Actions 页面。手动点 `Run workflow` 会出一个 APK 构件（artifact），适合先测试；如果已配置签名，它也是正式签名，可以直接覆盖安装。
>
> 没配置签名时的手动构件是 **debug 签名**，不能覆盖正式版。第一次装正式版前先卸载 debug 包，否则会提示「应用未安装」。

## 2. 自动更新怎么工作

- App 启动 5 秒后静默检查一次；两次自动检查间隔至少 6 小时（避免 GitHub 限流）。
- 检查地址：`https://api.github.com/repos/<仓库>/releases/latest`，版本号取 tag（`v0.1.0` → `0.1.0`）。
- 发现比当前 versionName 更高的版本 → 微信风格弹窗，显示版本号、大小、更新说明。
- 点「立即更新」：原生下载 APK 到缓存目录 → 校验大小 → 调起系统安装器。
- 第一次需要在系统里允许本应用「安装未知应用」；没有权限时 App 会直接跳到该设置页。
- 也可以在「设置 → 关于微信 → 检查更新」手动检查。
- 数据（聊天、朋友圈、设置、API Key、今日事件）都在 WebView 的 localStorage 里，覆盖安装不会丢。

发布新版本：

```bash
# 改 package.json 的 version 只是给手动构建用，正式版本号以 tag 为准
git add .
git commit -m "feat: ..."
git tag v0.2.0
git push origin main --tags
```

`versionCode` 由 tag 自动计算：`major * 10000 + minor * 100 + patch`，所以版本号要递增。

## 3. DeepSeek 网页端在手机上怎么用

电脑上是 Playwright 驱动一个可见 Chrome；手机上没有 Node，所以换成了 **App 内置 WebView**：

1. 设置 → AI 连接 → 打开「DeepSeek 网页端」开关。
2. 点「打开浏览器登录」，在弹出的窗口里登录 DeepSeek（手机号/邮箱均可），点右上角「完成」。
3. 登录状态存在 App 的 WebView 里，之后由后台隐藏页面完成输入和读取回复；每个好友复用各自的那条会话。
4. 清空聊天记录会让该好友下一条消息重新开会话。

实现位置：

- `src/lib/deepseekWebNative.ts`：输入、发送、等待回复、会话复用、限速、补设定的全部逻辑
- `native/android/DeepSeekWebPlugin.java`（生成 Android 工程后拷到 `android/app/src/main/java/com/lucky/wechatsandbox/`）：隐藏 WebView、登录窗口、执行 JS
- `src/lib/webBridge.ts`：电脑/手机两条路径的分发

已知风险（请在设置页也保留提示）：

- 这不是官方接口，违反 DeepSeek 使用条款，账号有被限制的风险；请求频率已经做了随机间隔和每小时上限。
- DeepSeek 网页改版可能让选择器失效（输入框、`.ds-markdown` 回复块）。出现「找不到网页端输入框」时，优先换用 API Key；需要修的话改 `deepseekWebNative.ts` 里的选择器和 `probe()`。
- 登录窗口用的是完整 Chrome 手机 UA，不带 WebView 的 `wv` 标记；如果站点仍然拦截，只能改用 API。
- 出现人机验证/滑块时程序会停手并提示，需要你在登录窗口里手动处理。
- 隐藏页面在 App 退到后台时会被系统降频，回复可能延迟；聊天时保持前台即可。

API Key 方式（DeepSeek / Gemini）在手机上是原生 HTTP 直连，不受浏览器跨域限制；Key 只存手机本地。

## 4. 代码结构（新增部分）

```
capacitor.config.ts               App 包名 / 名称 / webDir
shared/upstream.ts                DeepSeek/Gemini 调用与模型回退（电脑、手机共用）
src/lib/platform.ts               判断是否原生环境
src/lib/nativeHttp.ts             CapacitorHttp 直连
src/lib/events.ts                 每日事件：电脑写文件，手机写 localStorage
src/lib/webBridge.ts              网页端桥接分发
src/lib/deepseekWebNative.ts      手机 WebView 自动化
src/lib/updater.ts                检查更新 / 下载 / 安装
src/components/UpdateDialog.tsx   更新弹窗
src/screens/AboutScreen.tsx       关于微信（版本 + 检查更新）
.github/workflows/android.yml     tag → 构建 → Release
native/android/                   原生插件源码（生成 android/ 后拷入）
```

电脑端的 `/api/chat` 现在只是薄代理，时间与今日事件由前端拼进 system prompt，保证手机和电脑行为一致。

## 5. 本地构建（可选）

本机目前没有 JDK / Android SDK，默认走 GitHub Actions 云端构建。如果以后想在本机出包：

1. 安装 JDK 21 和 Android SDK（Android Studio 或 command-line tools），设置 `ANDROID_HOME`。
2. `npm install`
3. `npm run android:sync`
4. `cd android && gradlew.bat assembleDebug`（Windows）或 `./gradlew assembleDebug`
5. 产物：`android/app/build/outputs/apk/debug/app-debug.apk`

本机 release 打包需要设置环境变量 `KEYSTORE_FILE`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`。

改完原生插件后必须重新 `npx cap sync android`，否则 `android/` 里还是旧代码。
