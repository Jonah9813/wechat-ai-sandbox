### 1.3 更新链路

- 版本号来自 Android `versionName`；Release tag 去掉 `v`。
- App 启动 5 秒后查 `https://api.github.com/repos/<owner>/<repo>/releases/latest`，6 小时最多一次。
- 构建时 `VITE_GITHUB_REPO` 由 Actions 注入 `${{ github.repository }}`。
- 手动入口：我 → 设置 → 关于微信 → 检查更新。
- 下载 → cache/updates → FileProvider → 系统安装器；需要 `REQUEST_INSTALL_PACKAGES` +「安装未知应用」权限。
- **必须固定签名**，否则不能覆盖安装。

## 3. 手机端 DeepSeek 网页端的风险与调试

- 网页端是用户自己的登录会话，不是官方接口；已做随机间隔、每小时上限、连续失败暂停、验证码停手。
- 隐藏 WebView 放在 Capacitor 主 WebView 后面（全尺寸，索引 0），布局按手机宽度；不可见但不影响 DOM。
- 输入优先写 `textarea` 的 native value setter + input 事件；回车优先；失败再按位置找发送按钮。
- 回复读取 `.ds-markdown` 最后一块，2.4 秒不再变化视为完成。
- 若页面改版：
  1. 手机连电脑，Chrome `chrome://inspect` 调试 App 的 WebView（debug 包已开启 `setWebContentsDebuggingEnabled`）。
  2. 改 `src/lib/deepseekWebNative.ts` 的 `probe/typeText/pressEnter/clickSendButton/waitForReply`。
  3. `npm run android:sync` 后重新出包。
- 隐藏 WebView 不聚焦输入框，避免弹出键盘；contenteditable 分支仍会 focus。
- 登录窗口是原生 Dialog + WebView，使用完整 Chrome 手机 UA（不带 `wv`）。
- 手机端登录状态在 WebView cookie / localStorage；清 App 数据或换账号需要重新登录。
- 如果登录后被风控/滑块：只能让用户在登录窗口手动处理；程序检测到验证码会停止发送。

## 4. 自动更新的边界

- 仓库必须 public。
- GitHub API 未认证每小时 60 次；自动检查 6 小时一次，手动无限制。
- Release 必须有一个 `.apk` 附件；没有会提示「最新 Release 里没有 .apk 安装包附件」。
- 安装未知应用权限被拒时，原生插件会跳到系统设置页；用户回来后点「重试」。
- 下载中断会报错，不会安装半个包（校验文件大小 < 1KB 或不足 98%）。
- 更新弹窗的「以后再说」对同一版本只自动提示一次，手动检查仍会打开。
- 正式版与 debug 版签名不同，不能互相覆盖；第一次装正式版前先卸载 debug 包。
