### 1.3 更新链路

- 版本号来自 Android `versionName`；Release tag 去掉 `v`。
- App 启动 5 秒后查 `https://api.github.com/repos/<owner>/<repo>/releases/latest`，6 小时最多一次。
- 构建时 `VITE_GITHUB_REPO` 由 Actions 注入 `${{ github.repository }}`。
- 手动入口：我 → 设置 → 关于微信 → 检查更新。
- 下载 → cache/updates → FileProvider → 系统安装器；需要 `REQUEST_INSTALL_PACKAGES` +「安装未知应用」权限。
- **必须固定签名**，否则不能覆盖安装。

CI / 原生上踩过的五个坑（已修，别再改回去）：

1. 不能用 `android-actions/setup-android@v3`：它内部执行 `sdkmanager tools`，该包已被移除，会直接失败。现在改用 runner 自带的 SDK（`/usr/local/lib/android/sdk`）并自行调 `sdkmanager`。
2. Gradle 里不能写 `versionCode (System.getenv(...) ?: "1").toInteger()`：命令链歧义会让 AGP 拿到 null，报 `Value is null`。现在是先取变量再赋值（见下）。
3. 不能声明两个 `androidx.core.content.FileProvider`。第二个 authority（`.updater`）和 Capacitor 自带的 `.fileprovider` 共用同一个 provider 实例，系统安装器报 `authority ... does not match` 后闪退。现在统一用 `${applicationId}.fileprovider`，并让 `file_paths.xml` 暴露 `cache/updates`。0.1.0/0.1.1 因此不能自动覆盖安装，用户需手动装一次 0.1.2+。
4. JS 里的插件方法名必须和 Java 的 `@PluginMethod` 完全一致。`src/lib/deepseekWebNative.ts` 曾调用 `DeepSeekWeb.load()`，而 Java 里实际叫 `loadUrl()`，手机上报 “not implemented on android”。0.1.4 已统一为 `loadUrl`。
5. JS 里 `new KeyboardEvent(...)` 和 `el.click()` 造出来的事件 `isTrusted=false`，DeepSeek 前端会静默忽略——表现就是「字进了输入框，但消息发不出去」（0.2.1 及以前的报错）。发送必须走原生真实输入：`DeepSeekWeb.pressEnter()` → `WebView.dispatchKeyEvent(KeyEvent)`，或 `DeepSeekWeb.tapAt({x, y})` → `WebView.dispatchTouchEvent(MotionEvent)`（坐标是 CSS px，插件内部乘 density）。另外内置 WebView 设了 `setShowSoftInputOnFocus(false)`，否则 JS 聚焦输入框会弹输入法挡住页面。

界面约定：手机 App 用 Android 系统状态栏，**不要再渲染 `<StatusBar>` 模拟栏**，也不要用 `setOverlaysWebView(false)` 硬改 WebView 尺寸（在部分机型上仍会覆盖）。Capacitor 8 默认注入 `--safe-area-inset-*` CSS 变量，`html.native .screen` 用 `padding-top: var(--safe-area-inset-top)` / 底部同理把内容让到状态栏下方，背景保持 #111111；只有电脑预览才画模拟状态栏。聊天列表目标尺寸：导航栏 56dp、头像 48dp、行高约 73dp、头像与文字间距 14dp；通讯录索引为完整 A–Z + #。

用户侧现在不需要再做配置。本地改动后如果要重建原生工程，改 `native/android/` 里的源码，再跑 `node scripts/prepare-android.mjs`。

## 3. 手机端 DeepSeek 网页端的风险与调试

- 网页端是用户自己的登录会话，不是官方接口；已做随机间隔、每小时上限、连续失败暂停、验证码停手。
- 隐藏 WebView 放在 Capacitor 主 WebView 后面（全尺寸，索引 0），布局按手机宽度；不可见但不影响 DOM。
- 输入写 `textarea` 的 native value setter + `beforeinput`/`input` 事件（contenteditable 走 `execCommand('insertText')`，失败再退 `textContent`），这部分 JS 事件 React 是认的。
- 发送按可靠性依次尝试四次：原生真实回车 → 原生真实点击发送按钮（`sendButtonInfo()` 先找 aria-label/title/class 含 send/发送 的按钮，找不到就取输入框同一行最靠右的可见按钮）→ DOM 事件点击 → 再按一次真实回车；每一步都靠「输入框是否在 1.5 秒内清空」判定成功，全失败才报错，错误里带上输入框标签、是否找到按钮、按钮是否禁用。
- 回复读取 `.ds-markdown` 最后一块，基础等待 120 秒；页面出现「停止生成 / 思考中」时每轮顺延 30 秒，最多 4 分钟；生成中文字连续 12 秒不变才收尾。
- 每轮轮询都会检查页面文案，「服务器繁忙 / 网络异常 / 发送失败 / 请稍后再试 / 请求过于频繁 / 内容过长 / 对话不存在」会立即抛错，不走满超时。
- 同域名登录弹窗（手机号登录 / 扫码登录 / 登录后继续）会被识别为登录失效，直接提示重新登录，不再对着输入框空等。
- 发送失败或页面没有输入框时，清掉该好友的旧会话 id，下一轮重新开会话；连续失败会累计暂停。
- system prompt 最多 1200 字，避免网页端拒收超长内容。
- 超时错误会带上已等秒数、回复块数量、是否仍在生成、当前会话路径，真机出问题时让用户直接把这句话发回来。
- 若页面改版：
  1. 手机连电脑，Chrome `chrome://inspect` 调试 App 的 WebView（debug 包已开启 `setWebContentsDebuggingEnabled`）。
  2. 改 `src/lib/deepseekWebNative.ts` 的 `probe/typeText/pressEnter/clickSendButton/waitForReply`。
  3. `npm run android:sync` 后重新出包。
- 隐藏 WebView 不聚焦输入框，避免弹出键盘；contenteditable 分支仍会 focus。
- 登录窗口是原生 Dialog + WebView，使用完整 Chrome 手机 UA（不带 `wv`）。
- 手机端登录状态在 WebView cookie / localStorage；清 App 数据或换账号需要重新登录。
- 如果登录后被风控/滑块：只能让用户在登录窗口手动处理；程序检测到验证码会停止发送。

## 4. 自动更新的边界

- 仓库必须 public。
- GitHub API 未认证每小时 60 次；自动检查 6 小时一次，手动无限制。
- Release 必须有一个 `.apk` 附件；没有会提示「最新 Release 里没有 .apk 安装包附件」。
- 安装未知应用权限被拒时，原生插件会跳到系统设置页；用户回来后点「重试」。
- 下载中断会报错，不会安装半个包（校验文件大小 < 1KB 或不足 98%）。
- 更新弹窗的「以后再说」对同一版本只自动提示一次，手动检查仍会打开。
- 正式版与 debug 版签名不同，不能互相覆盖；第一次装正式版前先卸载 debug 包。
